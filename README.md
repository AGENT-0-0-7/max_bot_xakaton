# Рядом — локальные события в MAX

«Рядом» — мини-приложение для MAX, которое помогает жителю Тюмени быстро найти досуг в радиусе 25 км и подтвердить участие в событии. Организатор в том же приложении создаёт встречу и отслеживает её статус до публикации.

## Решаемая проблема

Приоритетный пользователь — студент или молодой специалист 18–35 лет, у которого есть свободное время в ближайшие дни. Сегодня ему приходится искать события в нескольких каналах, сопоставлять место, дату и свободные места, а затем отдельно уточнять запись у организатора.

Основной сценарий MVP:

1. Пользователь открывает чат-бота и мини-приложение «Рядом» в MAX.
2. MAX Bridge передаёт подтверждённые стартовые данные; приложение получает ближайшие опубликованные события.
3. Пользователь выбирает карточку, видит время, адрес, расстояние и остаток мест.
4. Нажимает «Записаться» и сразу получает подтверждение в интерфейсе и сообщение от чат-бота MAX.
5. При необходимости отменяет запись во вкладке «Мои планы».

Второй завершённый сценарий — организатор создаёт событие, получает статус «На модерации», а после одобрения в Django Admin оно появляется в ленте.

## Что реализовано

- адаптивный интерфейс мини-приложения для мобильного и веб MAX;
- подключение официального MAX Bridge через объект window.WebApp;
- серверная проверка подписи initData по алгоритму MAX и сроку актуальности 1 час;
- поиск опубликованных событий по координатам и радиусу, категории и свободным местам;
- атомарная запись без переполнения и повторная запись без создания дубля;
- отмена записи до начала события;
- создание, модерация и отмена событий организатором;
- вкладки «Мои планы» и «Организую»;
- отправка уведомления через MAX Bot API; в демо-режиме уведомление логируется и помечено как демонстрационное;
- webhook POST /webhooks/max/ для приветствия пользователя после запуска бота;
- OpenAPI и DATA-API конфигурация, тестовые данные, тесты API и Docker-конфигурация.

## Архитектура

    MAX chat-bot
           |
           +---- button / deep link ----> React mini-app + MAX Bridge
                                               |
                                  same-origin /api
                                               |
                                         Nginx reverse proxy
                                               |
                                    Django REST API + JWT auth
                                      |       |         |
                              PostgreSQL  Django Admin  MAX Bot API

Frontend использует тот же origin, что и API в Docker, поэтому CORS не нужен для основного сценария. В разработке Vite проксирует /api на Django.

## Быстрый локальный запуск

1. Скопируйте .env.example в .env. Для демонстрации оставьте MAX_DEMO_MODE=true; рабочий токен не требуется.
Подробная инструкция для Windows, демонстрация сценариев, проверка API, журналы, остановка и подключение настоящего бота описаны в [инструкции по запуску](ИНСТРУКЦИЯ_ПО_ЗАПУСКУ.md).
2. Запустите все компоненты одной командой:

    docker compose up --build

3. Откройте http://localhost:8080. API доступно напрямую на http://localhost:8100, админ-панель — http://localhost:8080/admin/.

Первый старт применит миграции и загрузит демонстрационные данные. Тестовый модератор: admin / admin_pass. Это только локальная учётная запись из seed-данных, не используйте её в публичном окружении.

Остановка без удаления данных:

    docker compose down

Повторный запуск:

    docker compose up

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| SECRET_KEY | секрет Django; в публичной среде задаётся случайным значением |
| DEBUG | выключите в production |
| DJANGO_ALLOWED_HOSTS | список доменов Django |
| MAX_BOT_TOKEN | токен бота из MAX для бизнеса; не хранится в репозитории |
| MAX_BOT_API_URL | https://platform-api2.max.ru |
| MAX_DEMO_MODE | true разрешает только явно помеченный mock-вход и отключает внешние уведомления |
| MAX_WEBHOOK_SECRET | необязательный секрет, проверяемый на webhook endpoint |
| MAX_WEBHOOK_URL | публичный HTTPS адрес webhook для регистрации подписки MAX |
| POSTGRES_* | параметры базы данных Docker |
| VITE_DEMO_MODE | разрешить браузерную демонстрацию локального стенда |
| VITE_API_BASE_URL | HTTPS URL API для отдельного размещения фронтенда; по умолчанию используется same-origin /api |

Не добавляйте настоящий токен бота, webhook secret или production SECRET_KEY в git.

## Данные и интеграции

Seed-данные — заранее подготовленная синтетическая афиша Тюмени. Это явно демонстрационные данные: приложение не заявляет интеграцию с внешней афишей. Для пилота источником могут стать выгрузки учреждений культуры и организаторов, а публикации проходят модерацию.

Реальная интеграция MAX:

- браузерный код подключает https://st.max.ru/js/max-web-app.js;
- MAX Bridge отдаёт window.WebApp.initData, а сервер проверяет его HMAC-подпись;
- после подтверждения записи Django делает POST /messages?user_id=... в platform-api2.max.ru;
- production webhook указывает на https://<ваш-домен>/webhooks/max/ и проверяет заголовок X-Max-Bot-Api-Secret.

## Порядок проверки

1. Выполните docker compose up --build.
2. Откройте http://localhost:8080. Браузер показывает фиолетовую плашку «Демо-режим» — это ожидаемо.
3. Выберите «Ближайшие события», откройте карточку и нажмите «Записаться».
4. Убедитесь, что кнопка меняется на «Вы записаны», а событие появляется в «Мои планы».
5. Нажмите «Отменить» и убедитесь, что запись исчезает, а остаток мест обновляется.
6. Откройте «Организую» → «Добавить событие», заполните форму. Новое событие получает статус «На модерации».
7. Войдите в Django Admin как admin, переведите событие в approved. Обновите ленту — событие появится среди доступных.
8. Для автоматической проверки API выполните команды из инструкции по запуску.

## API

Спецификация находится в openapi.yaml, конфигурация сценариев проверки — в DATA-API.yaml.

Основные endpoints:

- POST /api/v1/auth/max/ — обмен MAX initData на JWT;
- GET, POST /api/v1/events/ — каталог и создание события;
- POST /api/v1/events/{id}/register/ — запись;
- DELETE /api/v1/events/{id}/registration/ — отмена записи;
- POST /api/v1/events/{id}/cancel/ — отмена события организатором;
- GET /api/v1/users/me/registrations/ — планы участника;
- GET /api/v1/users/me/events/ — события организатора;
- POST /webhooks/max/ — MAX Bot webhook.

## Выход в MAX

Для доступного в MAX production-сценария нужны действия владельца верифицированного профиля MAX — это внешние права, которых нет в репозитории:

1. Создать и пройти модерацию бота в MAX для бизнеса, получить токен и поместить его только в защищённое окружение.
2. Разместить frontend и backend по HTTPS на домене с валидным сертификатом.
3. В настройках бота указать HTTPS URL мини-приложения и кнопку запуска.
4. Задать HTTPS адрес webhook и секрет в окружении, затем зарегистрировать подписку командой docker compose exec backend python manage.py setup_max_webhook.
5. Заменить base_url в DATA-API.yaml на публичный HTTPS адрес API.

После этого основной сценарий будет проходиться внутри чат-бота MAX без демо-режима.

Перед настройкой сверьтесь с [документацией MAX Bridge](https://dev.max.ru/docs/webapps/bridge), [подключением мини-приложения](https://dev.max.ru/docs/webapps/introduction), [проверкой initData](https://dev.max.ru/docs/webapps/validation), [методом отправки сообщений](https://dev.max.ru/docs-api/methods/POST/messages) и [подпиской Webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions). Названия методов, заголовок webhook и требования к HTTPS проверены по официальной документации на 28 сентября 2026 года.

## Ограничения MVP и развитие

- События пока модерируются вручную через Django Admin.
- Нет реальной интеграции с культурными афишами или картографическим геокодером; демо-афиша синтетическая.
- В production нужны наблюдаемость, резервные копии БД и очередь для повторной доставки уведомлений MAX.

Ядро, переносимое на другой город: поиск по координатам, статусы модерации, запись, личный кабинет и интеграция MAX. При масштабировании меняются каталог организаторов, локальная афиша, правила модерации, адресный справочник и партнёры. Логичный пилот — Тюмень с 10–15 учреждениями и студенческими организациями; метрики: доля завершивших запись, медианное время от поиска до записи, число отмен и доля опубликованных организаторами событий.
