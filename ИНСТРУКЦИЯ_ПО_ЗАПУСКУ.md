# Инструкция по запуску «Рядом»

Инструкция подходит для Windows 10/11 и Docker Desktop. Для демонстрации подключение MAX-бота и настоящий токен не нужны: Compose запускает отмеченный демо-режим с подготовленными данными Тюмени.

## Первый запуск

1. Установите и запустите Docker Desktop.
2. Откройте PowerShell в папке проекта.
3. Если файла .env ещё нет, создайте его из шаблона:

       Copy-Item .env.example .env

   Для локальной демонстрации оставьте MAX_DEMO_MODE=true и VITE_DEMO_MODE=true. Если .env уже существует, сохраните его и проверьте эти два параметра.
4. Соберите и запустите приложение:

       docker compose up --build -d

   При первом запуске Docker скачает базовые образы, создаст базу, применит миграции и добавит события для демонстрации.
5. Откройте приложение: http://localhost:8080.

Сервисы доступны по адресам:

- мини-приложение, API и Django Admin через один адрес: http://localhost:8080;
- Django API напрямую: http://localhost:8100/api/v1/events/;
- Django Admin: http://localhost:8080/admin/.

Логин модератора для локальной демонстрации: admin, пароль: admin_pass.

## Проверка сценария участника

1. На главной странице в демо-режиме отображается плашка «Демо-режим».
2. Выберите ближайшее событие в списке. Карточка показывает время, адрес, расстояние и число свободных мест.
3. Нажмите «Записаться». В демо-режиме приложение сообщит, что запись сохранена, а уведомление MAX отключено.
4. Откройте вкладку «Мои планы»: событие там сохранено.
5. Нажмите «Отменить»: запись исчезнет, место снова станет доступно.

Демо-пользователь сохраняется в браузере и получает отдельную запись в базе. Это нужно, чтобы действия в демонстрации были последовательными после обновления страницы.

## Проверка сценария организатора

1. Перейдите в «Организую» и нажмите «Добавить событие».
2. Заполните название, категорию, описание, адрес, координаты, время и лимит участников.
3. Нажмите «Отправить на модерацию». Событие появится в списке организатора со статусом «На модерации».
4. Откройте Django Admin, войдите как admin / admin_pass и одобрите событие.
5. Вернитесь в приложение и обновите список событий. Одобренное событие появится в ленте.

## Журналы и остановка

Посмотреть журналы всех компонентов:

    docker compose logs -f

Посмотреть состояние контейнеров:

    docker compose ps

Остановить приложение:

    docker compose down

Команда down сохраняет базу данных. Следующий запуск:

    docker compose up -d

## Автоматическая проверка API

Из корневой папки проекта в PowerShell выполните:

    $env:USE_SQLITE = 'true'
    $env:MAX_DEMO_MODE = 'true'
    .\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
    Push-Location backend
    ..\.venv\Scripts\python.exe manage.py check
    ..\.venv\Scripts\python.exe manage.py test
    Pop-Location

Встроенные тесты проверяют вход MAX и отказ демо-входа вне демо-режима, поиск рядом, создание события организатором, запись с лимитом мест, отмену записи и защиту webhook.

## Настройка настоящего мини-приложения в MAX

Локальный адрес http://localhost:8080 нужен только для демонстрации. MAX требует опубликованный HTTPS-адрес, действующий сертификат и чат-бота, созданного в MAX для бизнеса.

Перед настройкой задайте в защищённом .env:

- MAX_DEMO_MODE=false;
- VITE_DEMO_MODE=false;
- MAX_BOT_TOKEN — настоящий токен бота, выданный MAX;
- MAX_WEBHOOK_SECRET — случайная строка из латинских букв, цифр, подчёркивания или дефиса, длиной от 5 до 256 символов;
- MAX_WEBHOOK_URL — полный адрес https://ваш-домен/webhooks/max/;
- production SECRET_KEY, DEBUG=False и DJANGO_ALLOWED_HOSTS с вашим доменом;
- параметры PostgreSQL и HTTPS API при отдельном размещении.

Затем:

1. Разместите приложение на HTTPS-домене и откройте платформу MAX для партнёров.
2. Подключите URL мини-приложения к боту и выберите кнопку запуска.
3. Запустите команду регистрации подписки: docker compose exec backend python manage.py setup_max_webhook. Она передаст в MAX адрес, секрет и тип события bot_started.
4. Пересоберите frontend с VITE_DEMO_MODE=false и разверните backend с MAX_DEMO_MODE=false.
5. Откройте мини-приложение из чата с ботом в MAX и проверьте вход, запись и уведомление.

Нельзя публиковать .env или включать демо-режим на боевом домене.

## Что демонстрация не подключает

События Тюмени в seed-команде синтетические. Нет импорта из внешней афиши или картографической системы. Django Admin служит интерфейсом модерации. В демо-режиме MAX Bridge не выдаёт личность из MAX, а MAX Bot API не отправляет сообщения: приложение явно показывает, что уведомление не доставлено.
